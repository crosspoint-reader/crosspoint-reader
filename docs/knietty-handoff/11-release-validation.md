# Milestone 11 — Cross-platform and release validation

## Objective

Turn the proven prototype into a reproducible release candidate without
overstating hardware, Linux, macOS, security, or performance evidence.

## Preconditions

- Safe terminal state, v3, diagnostics, Rust parity, and TLS/pairing are complete.
- A display profile has passed Milestone 09; the viewport is optional.
- Official 1.5.0 OTA recovery and the normal SD application update remain proven.
- Every retained artifact has embedded commit, profile name, size, and SHA-256.

## Firmware matrix

At minimum build and identify:

- knietty safe 20 MHz release/control;
- selected adaptive profile only if its hardware evidence justifies inclusion;
- no accidental serial logging in terminal payload builds.

Run format, native tests, host tests, static checks where practical, safe build,
and any selected experimental build. Record linker RAM/flash and physical free,
minimum, and largest heap after Wi-Fi, TLS handshake, terminal activity, and
diagnostics.

## Device matrix

On the available China-locked X4 verify:

- Home icon, network selection, waiting tips, mapped approval/denial;
- first pairing and paired reconnect;
- 80 x 24 Terminus shell/tmux, btop, UTF-8 box drawing, ANSI basics;
- arrows, Enter, Escape, Ctrl+C, polarity toggle, two-press exit;
- host disconnect, reconnect, denial, diagnostic abort, and idle behavior;
- Terminal exit followed by reader use, sleep/wake, normal OTA, and SD update;
- battery/clock/header, margins, no stale hints, and no persistent display state.

Only list measurements generated by the versioned diagnostic suite. Keep safe
and selected adaptive results separate.

## Host matrix

Run independently on current Linux and macOS versions:

- unit/integration tests;
- automatic discovery and explicit IP;
- PTY geometry/environment, shell and tmux;
- Ctrl+C and Ctrl+\\ terminal restoration;
- default disconnect and daemon reconnect;
- pairing persistence, wrong-key rejection, revoke/re-pair;
- diagnostics smoke and JSONL validation;
- idle CPU/file descriptors and unplug/replug rediscovery.

Validate the systemd user unit on Linux and LaunchAgent on macOS as the user,
not root. Record exact OS versions. Do not claim parity until both are observed.

## Documentation and packaging

- Promote the project description and link this handoff from
  [`docs/knietty.md`](../knietty.md).
- Document Rust installation without hard-coded Homebrew paths.
- Document Rust installation, supported toolchain, and service paths.
- Document pairing, host revocation, trusted-LAN plaintext development mode,
  SD flashing, official OTA recovery, and the China-locked warning.
- Provide service templates that invoke absolute executable paths.
- Add a concise known-limitations section: E Ink cadence, glyph coverage,
  controller-specific experiments, and OS/device evidence.

## Complete when

Create a release candidate only when safe firmware recovery, Linux, macOS, TLS,
terminal controls, diagnostics, and reader sleep/wake all pass. Tag artifacts
from a committed tree and update `TTY_PROGRESS.md` with the last known-good
commit. Experimental binaries remain visibly labeled and separate.
