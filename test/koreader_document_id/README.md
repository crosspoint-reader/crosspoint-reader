# Document ID tests

These host tests compile the real `KOReaderDocumentId.cpp`. The storage fixture
emulates the signed `HalFile::read` contract, seek failures, short samples and file
closure. A host `MD5Builder` adapter uses OpenSSL for an independent MD5 digest.
The adapter records and rejects oversized hash feeds, so the regression against
the old unsigned conversion does not perform an out-of-bounds memory read.

Install the OpenSSL development package before configuring the host tests
(`libssl-dev` on Debian/Ubuntu). Linux and CI require it; other hosts skip this
suite with a status message if OpenSSL cannot be found. The firmware has no new
dependency.

From the repository root:

```sh
cmake -S test -B build/test -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build/test --target KOReaderDocumentIdTest
ctest --test-dir build/test -R '^DocumentId[./]' --output-on-failure
```

The generated byte fixture is `(position * 37 + position / 251) % 256`.
Its expected hashes come from Python's `hashlib.md5` applied to the concatenated
samples at offsets 0 and `1024 << (2 * i)` for `i = 0..10`. Samples past the
advertised file size are omitted, and the final sample is shortened only by the
file size. The tests do not require allocating a 1 GiB file to reach the final
official sample offset.

OpenSSL adapter failures are logged and recorded as GoogleTest failures, even
when the document-ID caller expects an empty result. The adapter preserves the
firmware's void API, clears its digest on failure and ignores subsequent calls.
Fault injection covers context allocation, initialization, update and finalization;
the tests check the diagnostic, context cleanup and persistent failure state.

This is host verification of sampling and error handling. It does not exercise
a physical SD card or the ESP32 ROM MD5 implementation.
